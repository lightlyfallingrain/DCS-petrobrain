# Testing & Provenance

- **Control-point tests must use externally-published ARPs, not DCS-derived points.** Early approach using pydcs's hardcoded `Damascus` point inflated the residual by ~1741m (the pydcs point itself was imprecise vs. live `coord.LOtoLL` output). M1 control points use SkyVector/eAIP real-world ARPs instead, avoiding circularity (Finding 3 of M1 verification note). Lesson: when validating a DCS extraction pipeline against external truth, ensure the external truth is actually independent, not recalculated from the same source.

- **Confidence field distinguishes third-party-fitted from live-install-verified parameters.** Syria's registry entry is `confidence="confirmed"` because Finding 1 reproduced 226 live DCS points to sub-cm residual; future theatres can be added with `confidence="provisional"` without code changes. This protects against silently encoding unverified community claims as fact, per project invariant (docs/CONVENTIONS.md).

- **A timed `thread.join(timeout=N)` returning tells you nothing about whether the thread finished — it returns the same way on timeout.** A concurrency test that only checks `join()`'s return and some shared counter can pass unchanged even when the thread is still blocked, if the counter happens to look the same either way. Always assert `not thread.is_alive()` after a timed join when the test's claim depends on the thread having actually completed; this is what caught a concurrency test on AA-6 that passed under a mutation breaking exactly the behavior it claimed to prove (review.md, 2026-10-20).

- **Hand-built fact/dict literals in a consumer's tests only prove the consumer parses a shape correctly — not that the producer ever emits that shape.** On `landmark-words-no-names` (F7, 2026-10-20), `speech.py`'s tests hand-built `SemanticFact.feature_id` strings (e.g. `"water:a river:Orontes"`) rather than deriving them from `enrichment.py`'s real `semantic_facts_for`; swapping the segment order in the actual producer passed the entire suite with zero failures. Whenever a change adds or changes an encoded-string or dict-shape contract between two modules, require at least one test that feeds the real producer's actual output into the real consumer, and verify it by mutation (reorder/rename a segment in the producer, confirm the suite goes red) rather than accepting "each end has its own unit tests" as coverage.
