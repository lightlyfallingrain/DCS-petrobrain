# Lua Export module architecture

- **A `pcall`-per-module loader's failure isolation holds only at the call site — a downstream table literal built from several modules' fields at once reintroduces a single point of failure, because table construction happens eagerly.** `ac-b12-export-modules` split `Export.lua` into `dofile`-loaded modules, each load wrapped in its own `pcall` so one module failing to load does not take the others down — the loader's own `call_if(mod, method, ...)` guard pattern enforces this everywhere it calls into a module. `commands.lua`'s first draft built its op-dispatch table as `local handlers = { cockpit_switch = effectors.handle_cockpit_switch_command, ... }`, indexing three different modules' fields directly inside one table constructor. If any one of those three failed to load, indexing its `nil` global raised a Lua error building the table itself — which `load_module`'s own `pcall` then caught as *`commands`* failing to load, taking all five dispatch ops dark, including the two owned by modules that loaded fine. The per-module `pcall` isolates a module's own load; it says nothing about a second module that reaches across module boundaries at its own load time. Fixed by guarding each table entry on its owning module being non-`nil` (`if petrovich ~= nil then handlers.petrovich_search = petrovich.handle_petrovich_search_command end`), the same posture the loader's own `call_if` already uses. General shape: in a design built around "one module's failure must not take down another," audit every place a *later*-loaded module's code touches *multiple* earlier modules at once (a dispatch table, a shared registry, a cross-reference) — table/collection construction is not lazy, so one bad reference inside it fails the whole construction, not just that one entry (`plans/ac-b12-export-modules/review.md` Required Fix).

- **A Lua test harness that extracts production functions by regex (`local function NAME(`) becomes a structural constraint on module design, not just a testing detail — cross-file helpers have to be bare globals, and a module's own entry points have to be written as `local function X() ... end; M.X = X` rather than `function M.X() ... end`, purely so the existing extraction technique keeps finding them.** Splitting one Lua chunk into several `dofile`-loaded files removes the free sharing a single chunk gave every local; the design that survived (`ac-b12-export-modules`) exposes shared helpers (`safe_call`, `json_escape_string`, `fmt_num_or_null`, …) as bare globals published via `_G.NAME = NAME` from `core.lua`, specifically because the test harness's `local function NAME(` extraction regex only matches that declaration shape — a plain `M.NAME = function(...) ... end` or direct table-method definition would both work at runtime and be invisible to the existing tests. The same constraint pushed every module to declare its own entry points as `local function xxx(...) ... end` followed by `M.xxx = xxx`, uniformly, even in files where no test currently needs that shape — so a *future* test can extract any entry point the same way without a second design decision. When refactoring code that an existing test suite extracts by pattern rather than by import, the extraction pattern is a live constraint on the refactor's shape, not an incidental detail to patch up afterward (`plans/ac-b12-export-modules/implementation.md` "Decisions Made"; `.claude/agent-memory/implementer/project_export_lua_split_test_harness_dictates_global_local_boundary.md`).

- **`core.lua`'s `json_escape_string(s)` returns the full quoted JSON literal (`"..."`), not a bare escaped body — a caller that wraps its return value in another pair of quotes produces invalid JSON silently (the whole line dropped by `collector/server.py`'s `_handle_line` on `JSONDecodeError`, no exception surfaced at the write site).** `ai_pilot_wheel.lua`'s `push_ai_pilot_wheel_state` had exactly this bug in its local `text_or_null` (`'"' .. json_escape_string(value) .. '"'`, producing `""FLT""`), live since the function was written, undetected because the resulting malformed line fails silently one layer downstream rather than at the call site. The other two correct call sites (`core.lua`'s own `encode_scalar`, `telemetry.lua`'s `name` field) use the return value directly. When adding a new JSON-emitting call site in this module family, call `json_escape_string` bare — never re-wrap it — and when a status line goes mysteriously stale on the collector side, check for this shape first (`plans/apw-status-json-quotes/debug.md`).
