# External Binaries & CLI Utilities

- **macOS `say` command silently falls back to default voice on unknown `--voice` argument.** Unlike typical CLI tools that error on invalid arguments, `say -v "Nonexistent Voice Name" "text"` exits 0 and produces audio in the system default voice, not an error. Do not rely on voice-name validation via the CLI — invalid voices must be caught in code or accept silent fallback behavior. Confirmed live during BL-10 implementation (2026-09-17). Implication: any voice-selection feature must either (a) validate against `say -v '?'` output before invoking `say`, or (b) accept that an invalid voice name degrades silently to default.

- **No standalone Piper TTS binary works on macOS — the archived release asset labeled "aarch64" is actually an x86_64 binary.** Piper must run as the `piper-tts` Python package (`pip install 'piper-tts[http]'`) in its own venv, pinned to an interpreter `onnxruntime` ships wheels for (measured: `python3.12` on Mac; Windows's only installed interpreter, 3.14, also worked). CLI-per-line synthesis costs ~2.7s/line; `piper.http_server`'s warm `POST /synthesize` is ~0.07s — any repeated-synthesis use needs Piper running as a long-lived HTTP server, never spawned per call. `piper.http_server`'s `-m`/`--model` CLI argument has no default and the process fails to start without it. (AA-6 recon + implementation, 2026-10-19/20.)

- **Win32 `winsound.PlaySound(..., SND_ASYNC)` has a single global sound slot per process.** A second overlapping async `PlaySound` call silently replaces whatever was already playing — unlike spawning an independent per-process player (e.g. macOS `afplay`), where overlapping calls each play independently. Code that needs genuinely overlapping/concurrent audio on Windows via `winsound` cannot get it from this API alone; accept "only the latest survives" or build mixing on top. (AA-6 recon Finding 5, 2026-10-20.)
