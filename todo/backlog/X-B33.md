# X-B33 — `/invariant-check` cannot see `contextlib.suppress(...)`

- [ ] **X-B33 — `/invariant-check`'s swallowed-exception row cannot see `contextlib.suppress(...)`,
  so the row stops meaning what its title says.** #status/open Found by the [[BL-11]] round-2 review, 2026-10-06.
  `.claude/skills/invariant-check/SKILL.md:122` greps `except ` followed by `pass$` only, which was
  the whole vocabulary for swallowing an exception in this repo when the check was written.
  `feature/bl11-tick-cost` introduces `contextlib.suppress(OSError)` around `close()` in two log
  writers — a **deliberate, reviewed** suppression, not a defect, which is exactly why it matters:
  the row will report a count that silently excludes a form the codebase now uses, and the next real
  swallowed exception written that way will not appear either.

  Widen the pattern to cover `contextlib.suppress(` and bare `suppress(` as well, keeping the row a
  WARN rather than a failure — the existing seven are pre-existing and intentional. **Worth doing
  before the next audit**, because a check whose title overstates its coverage is worse than no
  check: the previous audits that reported "7 swallowed exceptions" will read as complete.
