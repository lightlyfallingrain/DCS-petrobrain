# X-B35 — Provenance path resolution is hardcoded to audio-adapter, and the gate it feeds is red

- [ ] **`doc_provenance.py` resolves a bare `research/<file>.md` citation to `audio-adapter/`
  unconditionally, so `doc-provenance-refresh.sh` aborts before writing anything — and
  `doc-provenance-gate.sh` is consequently red and deliberately unwired.** #status/open Filed
  2026-10-09 by the DoD gate on `feature/doc-conventions-audio-adapter`
  (`plans/obsidian-links-and-tags/dod-check.md`, RF-DoD-1).

  **The defect.** `doc_provenance.py:201`:

  ```python
  target = f"{sub}/research/{filename}" if sub else f"audio-adapter/research/{filename}"
  ```

  This is review finding RF4-9's hardcode surviving in the *path-resolution* half of the same file:
  RF4-9 generalised entry **discovery** from `audio-adapter/ROADMAP` to all seven split directories
  (22 → 245 entries), and resolution was left behind. Measured: **17 of the 19**
  `audio-adapter/research/` missing-document failures exist under another subproject —
  `mi24p-command-surface.md` → `aircraft-layer/`, the six `m1`–`m7` recon notes → `world-model/`,
  the three `miz-*` notes → `mission-interpreter/`, `2026-10-05-performance-review.md` →
  `body-layer/`. Two are genuinely absent. A further 21 missing-document failures cite
  `plans/<f>/plan.md` files that do not exist (`plans/bl11-tick-cost/` has none;
  `plans/post-review-fixes/` holds only `explore-notes.md`) — that is data to correct, not code.

  **A fixed prefix cannot be made correct by changing the default.**
  `2026-10-05-security-audit.md` and `2026-10-05-performance-review.md` each exist in *two*
  subprojects. Resolution has to be relative to the citing entry's own subproject, and the
  genuinely ambiguous case has to be refused rather than guessed.

  **Observable symptom**, which is how to know it is fixed:

  ```
  $ python3 .claude/scripts/doc_provenance.py check
  doc-provenance-refresh: ERROR: cited document missing: audio-adapter/research/mi24p-command-surface.md
  ```

  **Why the gate is red and why that was accepted rather than fixed.**
  `doc-provenance-gate.sh` exits 1 naming **126 documents**. It is **not** wired into
  `commit-quality-gate.sh`, deliberately, and nothing else runs it
  (checked: `.claude/settings.json`, `install-git-hooks.sh`, `.git/hooks/`). The reason is not that
  126 blocks rotted — **120 of those documents have no block at all.** The regeneration diff is
  purely additive: 230 citation lines added, zero removed. So the gate is **ahead of the work it
  checks**: `plans/obsidian-links-and-tags/plan-document-graph.md` Stage B step 2 is *"run over
  `*/research/`, `docs/acceptance/` … commit the blocks"*, and that stage has never run because the
  user paused it. Wiring the gate would refuse every commit touching any `ROADMAP/` path, repo-wide,
  because a paused stage has not been built — a nonsense gate rather than a quality one, and the
  cries-wolf-gets-bypassed failure the parent plan's R4 names.

  **The published unblock condition was wrong, which is the other half of this item.** The wiring
  site and `docs/DOC_CONVENTIONS.md` said to run `doc-provenance-refresh.sh` once the
  document-graph work unpauses. That command aborts, per the defect above. So the real order is:
  **fix the resolution, then regenerate, then wire the gate.** Also stale in the same vein:
  `doc-provenance-refresh.sh`'s own header still describes its scope as documents cited by
  `audio-adapter/ROADMAP/AA-*.md`, understating its blast radius about sixfold in the one place
  someone looks before running it.

  Blocks [[X-B29]]-style provenance work generally, and is a prerequisite for Stage B of the
  document graph rather than part of it.
