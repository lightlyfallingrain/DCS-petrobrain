### Risk: unbounded `response.read()` on Piper's success-path WAV response

**Finding:** `PiperEngine.synthesize` (`tts_engine.py:121-122`) reads Piper's successful response
body with no size cap, unlike the error-excerpt path three lines below it which is explicitly
bounded to 200 bytes.
**Location:** `audio-adapter/src/tts_engine.py:121-122`
**Probability:** low — Piper is a loopback-only (`127.0.0.1:7800`, verified above), same-machine,
operator-started process; there is no network path for an attacker to make it return an oversized
or malicious body without first compromising the local machine, at which point this is far from the
weakest link.
**Impact:** low — at worst, a misbehaving Piper process could make `audio-adapter` buffer a large
response into memory (a self-inflicted local DoS against one `/speak` call, same machine), not
remote code execution or data exposure.
**Recommended action:** optional hardening — if this project wants bounded reads on every HTTP
client call it makes as a matter of policy, add a cap (e.g. read in chunks up to a bound, raise
`TTSSynthesisError` beyond it) consistent with the existing bounded-`Content-Length` posture already
enforced on the *inbound* `server.py` side. Not required for this feature's trust model.

Options:
  (A) Ignore — document acceptance of this risk (trusted, loopback-only, same-machine peer)
  (B) Add to backlog — bound the read for defense-in-depth, consistent project-wide HTTP-client policy
  (C) Fix now
  (D) Stop — do not proceed until resolved

**Not filed as a backlog item, intentionally.** This is a defense-in-depth suggestion against a
trusted, loopback-only, operator-controlled peer, with no realistic attack path in this project's
single-user/LAN-only trust model (root `CLAUDE.md`, "Scope"). Filing it would create backlog noise
disproportionate to the risk; if the user wants it hardened as general policy across every HTTP
client in the repo (not just this one), that is a cross-cutting backlog item broader than this
feature and belongs to a future audit that looks at all such clients together, not this one in
isolation.

### Verdict

**APPROVED**

No exploitable vulnerability, no known CVE on the new external tool's reachable surface (it is

`POST /download` which fetches arbitrary voices from the internet — is correctly done on both
`run-piper-mac.sh` and `run-piper-windows.sh`.
