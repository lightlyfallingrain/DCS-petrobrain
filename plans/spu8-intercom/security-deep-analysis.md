### Verdict

### Required Fixes (if any)

1. **`scale_wav_volume` can raise `ValueError` (odd-length PCM data from a truncated/malformed WAV) outside its own guarded block, and nothing in `_run()` catches it — this kills the playback worker thread permanently and silently, with the LAN API continuing to report success for every subsequent `/audio/play` call.** — `aircraft-layer/src/collector/audio_sender.py:188-229` (widen the except clause / wrap the array steps) and `:408-435` (defense-in-depth: wrap the `scale_wav_volume` call in `_run` the same way `self._player.play` already is). Reproduced empirically with a crafted WAV (declared `nframes` larger than the actual truncated data chunk, data chunk length odd) — `python3 -m wave` opens it cleanly, `readframes` returns the truncated (odd-length) bytes without raising, and `array("h").frombytes()` on those bytes raises uncaught. A regression test should cover this specific case (odd-length PCM data surviving to the `frombytes` call), since the existing `test_scale_wav_volume_handles_a_malformed_file` test only exercises a file that fails at `wave.open` itself and does not reach this line.
