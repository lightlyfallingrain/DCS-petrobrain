# Contacts callout — one group-shaped line per clock hour for contacts that do not group

Plan for `feature/contacts-callout`, 2026-10-16. Closes the judgement half of
`todo/todo/X-T4.md`, open since 2026-09-28.

**The specification is `docs/acceptance/2026-10-16-contacts-callout-direction.md`** — the user's
own words across three rounds, every field settled, with a worked transcript at §4c. Where this
plan and that document disagree, that document wins. Decisions marked **(user)** below come from
that conversation; decisions marked **(code)** come from reading the modules and are mine to be
overruled on.

### Goal

Speak one group-shaped line per clock hour — *"&lt;hedge&gt; contacts, &lt;classes&gt;, &lt;hour&gt;
o'clock, &lt;range or span&gt;"* — for the ungrouped contacts sharing that hour, in place of their
individual detection lines, delta-gated so it is silent until the hour's content changes.

**Whose job, in one line:** it tells the pilot which bearing holds how much of what, in one sentence
per bearing instead of sixteen, so the fact he needs in order to turn away or line up arrives while
it is still true — the 2026-09-28 sortie delivered the same information as 160 lines over half an
hour, by which point every one of them was stale.

---

### Correction to the dispatching brief: `group_candidates` does not exist

The brief asks the plan to explain why `belief.callouts.group_candidates` "almost never fires
today". It fires never, because **the function was deleted** — retired by
`plans/group-reporting/plan.md` Stage 4 once a real `belief.groups.Group` took over the event-level
case (`belief/callouts.py` module docstring, "Group disclosure now speaks for its members"; verified
by `grep -rn "def group_candidates"`, zero hits). What survives is:

| what | where | reachable from |
|---|---|---|
| `group_facts` (bucket on `(unit word, range word)`, chain by clock) | `callouts.py:765` | **pull path only** — `CrewConsole._handle_report` |
| `render_group_report` | `speech.py` | same |
| `_chain_by_clock` | `callouts.py:691` | `group_facts`, sole caller |

So **the push path has no report-space aggregation at all today.** Every ungrouped contact speaks
its own `CONTACT_DETECTED` line; the only aggregation on that path is a real `Group`'s disclosure.

**This feature replaces `group_candidates`'s former role on the push path, with a deliberately
coarser key, and does not touch `group_facts` on the pull path.** The two reasons the old key could
not work, both measured in `plans/contact-fragmentation-at-range/2026-09-28-log-analysis.md`:

1. **It required simultaneity.** Detections arrived at 4.8–5.4/min, roughly one every eleven
   seconds, against a `CALLOUT_MAX_AGE_S` of 10 s — so the event pool almost never held two at
   once. **Consequence for this design: a set cannot be built from the event pool.** It must be
   derived from the *store*, with a live event acting only as the trigger. This is the single most
   load-bearing fact in the plan and it is the one an event-pool design would get wrong.
2. **The range word was part of the key.** `_format_range_km` puts `"2 kilometres"` and
   `"2.5 kilometres"` in different buckets, so two vehicles 400 m apart in depth never aggregated.
   The user settled this directly — *"one line: 2 to 6 km"* — so **range is a rendered field, never
   a key** (user).

The pull path degenerates for the same reason (`report` answering with three separate group lines
because their range words differ, quoted in that log analysis). **Out of scope here** — file it as
a `BL-B` backlog item rather than widening this feature.

### Decisions

**Decision 1 — the signal word and the line form.** *(user, §4c)*

> *"&lt;hedge&gt; contacts, &lt;classes&gt;, &lt;clock hour&gt; o'clock, &lt;range or range span&gt;."*

`"contacts"`, never `"group"`. Sourced through the existing
`_plural_unit_type_display("OP_GROUPSOMETHING", "presence")`, which already returns exactly that
word — so the vocabulary stays single-sourced rather than acquiring a second literal. Bearing is
**mandatory and never omitted** (user: *"o'clock position is a must"*). Classes are an array, and
are **omitted entirely** when no member is differentiated — which is also, without any new
mechanism, the low attention tier's specified content (see "Relation to the attention tiers").

**Decision 2 — a set is a derived per-tick view, not stored state.** *(code)*

`contact_sets(store, ownship, now_sim) -> list[ContactSet]`, a pure function, recomputed every tick.
Nothing is persisted on `Contact` or in the store. This is `group_view.collapse_members`' posture,
not `GroupStore.reconcile`'s, and the reason is that a `Group` is a *belief* (two vehicles are
together) that must survive looks, whereas an hour-bucket is a *reporting* artefact of where ownship
is pointing right now and has no meaning to persist. It also means no reconciliation, no split/merge
bookkeeping, and no new store surface.

The only state kept is the scheduler's own answer to "what have I already said", which is where that
state already lives for every other channel (`_last_spoken_signature`, `_last_spoken_sim`,
`Group.last_spoken_*`).

**Decision 3 — the set view never calls `describe_contact`, and this is what makes the feature
cheap.** *(code — and it is the one boundary a future touch must re-check)*

`ContactSet` is derived from `Contact.last_position` / `.classification` / `.cardinality` / `.id`
plus `OwnshipState`, via `enrichment.relative_geometry`, which is pure arithmetic over x/z/alt.
**It must not reach `describe_contact`, `WorldEnrichmentCache.get_or_compute`, `semantic_facts_for`,
`terrain_divide_qualifier`, or a `sqlite3.Connection`** — the same prohibition `group_view.py`
carries, for the same reason and with a measured number behind it:
`.claude/agent-memory/performance-reviewer/project_group_collapse_perf.md` records
`describe_contact` enrichment at **63.25 ms cold / 6.77 ms warm per contact**, cache-missing by
construction for a re-observed contact. At the measured n=52 ungrouped contacts that is ~350 ms per
poll against BL-11's 12.6 ms budget. A set view built on facts dicts is not a slower version of this
design; it is an unshippable one.

Two consequences to accept explicitly:

- **The clock hour is bit-identical to what `describe_contact` would give**, because
  `perception.geometry.bearing_deg` reads only `x`/`z` and the terrain-aware altitude correction
  cannot move it. Verified by reading both functions, not assumed.
- **The range can differ by a few metres**, because `describe_contact`'s `relative_now` uses the
  terrain-corrected `world_position` altitude and this uses `Contact.last_alt_m`. At 2–6 km a 100 m
  altitude difference moves slant range by under 3 m, against `_format_range_km`'s 500 m rounding.
  Accepted; stated so a future reader does not read it as a bug.

**Decision 4 — a new small renderer, not `render_group_disclosure`.** *(code)*

`render_group_disclosure` is bound to a persisted `Group` in four places
(`last_spoken_signature`, `last_spoken_member_contact_ids`, `last_spoken_leading_contact_id`,
`last_spoken_differentiated`) and carries threat-leading, movement state and the spoken-extent
guard. Reusing it would mean either synthesising a fake `Group` or threading an abstraction through
a 300-line taxonomy — and a contacts set deliberately makes *no* associative claim, so its line
should not be able to say *"Now leading: SRSAM"* or *"still moving north"* about a set that is not a
formation.

So: `render_contacts_line(...)` in `speech.py`, composed **entirely from existing primitives** —
`_cardinality_phrase`, `_plural_unit_type_display`, the composition clause, `_format_range_km`. It
adds vocabulary nowhere. It returns an `OutgoingSpeech` with a `content_signature`, exactly as
`render_group_disclosure` does.

**Decision 5 — share the composition clause's word-rendering half.** *(code)*

`_group_composition_clause(member_facts)` already does the right thing: `collapse_members` at
`CollapseDepth.TYPE`, exact per-class counts via `_SPOKEN_NUMBERS`, and one aggregated trailing
phrase for undifferentiated members (*"truck and something"*). Its only obstacle is that it takes
facts dicts and rebuilds synthetic `Contact`s from them (`_contact_for_member_facts`) — while the
set view holds real `Contact`s already.

Split it: `_composition_words(leaves: Sequence[CollapseNode]) -> str` (the word half, which is all
of the current body below the `collapse_members` call), with `_group_composition_clause` kept as the
facts-taking wrapper and a `_contacts_composition_clause(contacts)` added beside it. This is a named
duplication removed, not a new abstraction — the alternative is the same forty lines twice.

**Its existing precondition carries over and must be honoured by the caller:** it must not be called
with an empty sequence or with *only* undifferentiated members. For a contacts set that is the
**common far case**, so the caller omits the class field rather than calling it. The current
`assert` in that function stays, and a test asserts the caller never trips it.

**Decision 6 — the count is a hedge over summed cardinality intervals, and `attended` is always
false.** *(user for the register, code for the arithmetic)*

`_cardinality_phrase(sum(lo_i), sum(hi_i), attended=False)`. Summing intervals is the honest reading:
each contact carries its own belief about how many real objects it stands for, and the set's count is
their sum, not `len(contacts)`. `attended=False` is not a choice — watched contacts are excluded from
sets entirely (Decision 8), so no exact-count claim can ever be laundered into a hedged set line.

The register is unchanged: `"couple"` (2–3), `"handful"` (4–5), `"several"` (default plural),
`"many"` (16+). *"&lt;few/several/many&gt;"* in the direction's §4a names this register, not three
literal words (user, §4c.2). **See Open Decision A** — the shipped register drops articles, and the
direction's own mock does not.

**Decision 7 — one line per hour; range is rendered, never a key.** *(user, §4c.1)*

A set straddling 1 and 2 o'clock is **two** callouts. The bucket is
`enrichment._clock_position`'s existing 30° hour — reused, not re-declared, so a set line and a
single contact's line can never disagree about which hour something is in. **No chaining**:
`CALLOUT_GROUP_CLOCK_SPAN_HOURS` / `CALLOUT_GROUP_MAX_SPAN_HOURS` and `_chain_by_clock` belong to
the pull path's `group_facts` and stay there untouched.

Range renders as `_format_range_km(nearest)` when nearest and farthest round to the same word, else
`"{nearest} to {farthest}"` — *"2 to 4 kilometres"*. The threshold is `_format_range_km`'s own 500 m
rounding, derived rather than chosen, so it is **not** a new constant.

**Decision 8 — three exclusions from set membership, each with its own reason.** *(code; (a) is user)*

A contact is excluded from every set when:

- **(a) it is watched or priority.** User, §4c.3: *"current watched contact behaviour stays"*, and
  the brief's *"a contacts line must not swallow them."* It keeps its own line and its own exact-count
  path. Must be read without routing through `describe_contact` (`belief.attention`'s own accessor);
  the implementer resolves which call that is, under Decision 3's prohibition.
- **(b) it belongs to a `belief.groups.Group`.** The group's own disclosure speaks for it; folding
  it into a set as well would produce two lines about one thing, which is the defect
  `plans/redundant-group-disclosure/` exists to prevent.
- **(c) it is a merge echo of a strictly-earlier-founded, live, plausibly-same contact** —
  `callouts._is_merge_echo_of_earlier_contact`, the predicate `_render_event` and
  `_already_reported_member_ids` already share. Without this, a merge echo is suppressed from
  speaking its own line (as today) but still inflates the set's hedge and composition, so the one
  thing the line exists to deliver — how much of what is out there — would be systematically wrong
  in exactly the scene the feature targets. **This is the costliest exclusion** (O(n²) pairwise gate
  evaluations); Stage 4 measures it, and Risk 2 names the fallback.

Plus the gate every other candidate passes: **`store.callout_observable(contact, now_sim)`**, the
no-omniscience invariant. Applied **per member** here, not "any member" as the `Group` branch does:
a `Group` is a believed formation whose line is rendered from its nearest member, so one straggler
behind the doorframe should not silence it; a set is a bare population count over an hour, so an
unobservable contact must not be counted into it at all. Different question, different answer —
stated because the asymmetry will look like an oversight otherwise.

**Decision 9 — the delta: what makes an hour speak.** *(user for "delta only"; code for the triggers)*

Per-hour `content_signature` = **hedge word + class clause only**. Clock and range are excluded,
exactly as `render_group_disclosure` excludes them, and for the identical measured reason
(`plans/group-undermerging/debug.md`: a group re-spoke its whole composition every ~500 m of opening
range). So an hour speaks when, and only when:

1. it has never spoken (and is not fully covered — Decision 10), **or**
2. its class set changes — a class appears or disappears, **or**
3. **its hedge word changes** — the hour crossing couple → handful → several → many.

Trigger 3 is mine and is **Open Decision B**. It is what makes a filling hour audible at all: at
most four lines for sixteen vehicles, each one telling the pilot the hour is getting worse. Without
it, vehicles two through sixteen are silent and he never learns the hour filled up.

Minimum set size is **2** (user's own §4c mock: *"A couple of contacts, trucks, 2 o'clock, 6
kilometres"* is a two-member set). So a second ungrouped contact arriving in an hour switches that
hour from individual lines to the set line.

**Decision 10 — the two cross-mechanism edits, which are where this feature can go wrong quietly.**
*(code)*

- **A set member's own `CONTACT_DETECTED`/`CONTACT_REACQUIRED` is skipped without being consumed**
  in `tick`'s event loop — the identical treatment, in the identical place, that a grouped contact's
  detection already gets. *Skipped, not consumed*, so a contact whose set dissolves still gets its
  own line. **Only those two kinds.** `CONTACT_CLASSIFICATION_CHANGED` is never folded, per
  `callouts.py`'s own standing rule: *"aggregating a specific identification into a generic count is
  exactly what would make a BTR-70 disappear into 'three infantry'"*. `_WATCHED_ONLY_KINDS` cannot
  arise for a set member at all, by Decision 8(a).
- **When a set line speaks, its members are recorded as covered**, into a new
  `_covered_by_contacts_line: set[str]`, and their pending detection events are acknowledged —
  mirroring the `Group` branch's own `acknowledge_event` loop. `_already_reported_member_ids` then
  gains **branch 3: `contact_id in self._covered_by_contacts_line`.**

  **This second edit is not optional and is easy to miss.** Without it, a set member that later
  joins a real `Group` is unknown to `_already_reported_member_ids` (which only reads
  `_last_spoken_signature`, populated solely by *individual* lines), so the new `Group` fully
  discloses a roster the pilot has just heard as a contacts line — reintroducing precisely the
  redundancy `plans/redundant-group-disclosure/plan.md` fixed, through a door this feature opens.

  A **separate** set rather than writing into `_last_spoken_signature`: that dict's value is the
  exact text an individual line last produced and is compared byte-for-byte in `_render_event`.
  Writing a set line's text into it would overload one field with two meanings — the shape of defect
  this project has paid for repeatedly.

**Decision 11 — a min-gap on re-speaks only.** *(code)*

`CONTACTS_LINE_MIN_GAP_S`, per hour, mirroring `WATCH_REPORT_MIN_GAP_S`'s role. **A never-spoken
hour is exempt**, so a first disclosure is never delayed. This exists for oscillation: a contact
sitting on an hour boundary, or ownship yawing, can move a set between adjacent hours and re-speak
on the new hour's empty signature. The gap bounds how often that can be heard.

An hour's signature is **dropped when the hour no longer has a set**, so flying past and later
re-acquiring an hour speaks afresh. Deliberate: after a turn the words are news again.

The stronger fix — carrying a signature across an hour change when the new hour's members
majority-overlap the old hour's, the greedy-overlap pattern `GroupStore.reconcile` already uses — is
**Stage 5, conditional on Stage 3 showing jitter.** Not built speculatively.

### Co-moving Fields

Step 6a's trigger fires only partly — this is not a phase machine and nothing here is written by a
pilot command. But four pieces of "what has already been said" now move together across three
mechanisms, and `BL-B64`'s lesson is that a divergence no test constructs by accident is a
divergence review finds one field at a time. So:

| Field | Written by | Transition | Must hold true after |
|---|---|---|---|
| `_last_spoken_contacts_signature[hour]` | `tick`, set branch | a set line speaks | equals that line's `content_signature`; clock/range are **not** in it |
| `_last_spoken_contacts_signature[hour]` | `tick`, set derivation | the hour's set falls below 2 members, or vanishes | the entry is **removed**, not stale-kept |
| `_covered_by_contacts_line` | `tick`, set branch | a set line speaks | contains **every** member id of the set that spoke, so `_already_reported_member_ids` branch 3 sees them |
| member `CONTACT_DETECTED`/`REACQUIRED` events | `tick`, set branch | a set line speaks | **acknowledged** (as the `Group` branch does), so they cannot resurface |
| member `CONTACT_DETECTED`/`REACQUIRED` events | `tick`, event loop | contact is in a set, no line spoken yet | **skipped, not consumed** — the contact must still get its own line if the set dissolves |
| `_last_spoken_signature[contact_id]` | `_render_event` only | a set line speaks | **unchanged** — a set line must never write here (Decision 10) |
| `Group.last_spoken_*` | `mark_group_spoken` only | a set member joins a `Group` | unchanged by this feature; the `Group`'s first disclosure must see branch 3's coverage |

The test that would have caught `BL-B64` in this shape: construct a contact covered **only** by a
set line (never individually spoken), put it into a `Group`, and assert the group's first disclosure
is silent or a delta — never a full roster. Every naive fixture populates `_last_spoken_signature`
and `_covered_by_contacts_line` together and cannot build that state.

### Relation to the attention tiers

`docs/acceptance/2026-10-13-group-model-and-attention-tiers.md` Part 3 specifies the information
content per tier. This callout is that document's **low and medium tier reporting shape**:

| tier | its specified content | how this line delivers it |
|---|---|---|
| low (beyond class detection) | `<where>` + far/mid + few/several/many | hour + range span + hedge; the class field is **absent**, because every member is still `presence`-level and Decision 5's caller omits it |
| medium (≤ 5 km) | the above + rough classification | the same line, with the class clause present, because members have differentiated by then |
| high (watched/selected) | per-class counts, individual positions | **not this line** — excluded by Decision 8(a) |

**Nothing here presumes a tier mechanism, and there is none.** No tier field exists; that document's
own consequence 4 says the tiers *"overlap existing machinery and must be reconciled, not
reinvented"*, and consequence 1 says `BL-14` needs an attention-driven resolution mechanism that
does not exist. The low/medium split falls out for free from **classification depth already in
`Contact.classification`** — a far contact is `presence`-level, so the class clause is empty. That
is an emergent property of existing state, not a tier being implemented, and the plan introduces no
third concept beside `Attention`/`effective_attention`.

### Implementation Plan

**Stage 1 — the derived view and the renderer, wired to nothing.**
`belief/contact_sets.py`: a frozen `ContactSet` (`clock_hour`, sorted `contact_ids`,
`nearest_range_m`, `farthest_range_m`, `units_lo`, `units_hi`) and `contact_sets(store, ownship,
now_sim)`. `speech.render_contacts_line(...)` plus Decision 5's split of
`_group_composition_clause`. `tests/test_contact_sets.py` and `test_speech.py` additions, including
the direction's §4c transcript as a literal table of worked cases, the all-undifferentiated case
(class clause absent), the same-range-word case (single figure, not a span), and a test asserting
the composition clause's `assert` is never reachable from this caller. No behaviour change — nothing
calls either function yet. Independently reviewable and fully testable.

**Stage 2 — wire it into `CalloutScheduler.tick`.** Third candidate source, scored into the existing
shared list. It needs a `group_priority`-shaped tuple: `(_DEFAULT_THREAT_BAND, -best_rank,
nearest_range_m, -now_sim)` with `best_rank` the default — every set member is unwatched by
construction, so a set never outranks a watched contact's own line. Then Decision 9's per-hour delta
gate, Decision 10's two cross-mechanism edits, Decision 11's min-gap. A replay-determinism test, as
`test_callouts.py` already has for the scheduler: nothing here may read wall clock.

**Stage 3 — validate against the sortie that raised this.** Replay the 2026-09-28 belief-truth log
(`sortie-log-triage` skill, and the `eyesight_replay` tool) and count spoken lines. The baseline is
**~160 lines over 30 minutes, one every ~11 s, nearly all the same words.** Two acceptance bounds,
and the second is the one that can fail quietly: (a) total lines fall substantially; (b) **no hour
that held contacts goes unreported** — a fix that is merely quiet is the failure mode here, not a
success. Also check for hour-boundary oscillation, which decides whether Stage 5 is needed.

**Stage 4 — measure the per-tick cost.** `contact_sets` is pure arithmetic, so the prediction to
falsify is **under 1 ms at the measured n=52**, against BL-11's 12.6 ms poll. Measure the two parts
separately: the bucketing (`relative_geometry` per contact, trivially linear) and **Decision 8(c)'s
merge-echo exclusion, which is O(n²) pairwise `contacts_plausibly_same`** — 2,652 gate evaluations
at n=52. Measure it; do not reason about it. Benchmark in `plans/contacts-callout/scratchpad/`.

**Stage 5 — conditional refinement.** Only if Stage 3 showed hour-drift jitter: carry a signature
across an hour change on majority member-id overlap, per Decision 11.

### Constants

**Tunable** (declared through `tuning.*` with `lo`/`hi` and a `#:` comment, per root `CLAUDE.md`'s
X-T26 rule) — both change what Petrovich says:

| key | accessor | default | lo / hi | status |
|---|---|---|---|---|
| `belief.contact_sets.CONTACTS_SET_MIN_MEMBERS` | `tuning.whole` | `2` | 2 / 8 | `judgement` |
| `belief.callouts.CONTACTS_LINE_MIN_GAP_S` | `tuning.real` | `8.0` | 0.0 / 30.0 | `judgement` |

**Check the rendered `config/defaults.toml`, not the `#:` comment** — the generator emits **only the
first sentence**, which is where every `X-T26` defect has hidden. So for `CONTACTS_LINE_MIN_GAP_S`
the *first* sentence must carry the coupling, not a later one: it interacts with
`CALLOUT_MAX_AGE_S` (10.0, not itself tunable), and no per-key bound can see that — the same class of
cross-key coupling `tuning.py`'s own docstring documents for `OBSERVED_WINDOW_S`. A `hi` above
`CALLOUT_MAX_AGE_S` is permitted because it cannot silence an hour permanently (the set is
store-derived and never expires, so it speaks at the next gap expiry), but it *can* delay a re-speak
past the member events' own retirement, which is worth a reader knowing. `hi` of 30.0 keeps that
bounded.

**Deliberately not tunable, each for a stated reason:**

- **The clock-hour bucket width** — it is `enrichment.CLOCK_BUCKET_DEG`, already existing and shared
  with every other spoken bearing. Re-declaring it here would let a set line and a contact line
  disagree about which hour something is in.
- **The range-span threshold** — derived from `_format_range_km`'s own 500 m rounding, not an
  independent number (`_GROUP_SPOKEN_EXTENT_GUARD_M`'s own docstring makes exactly this argument).
- **The signal word `"contacts"`** — vocabulary, not a behaviour knob, and sourced from
  `_plural_unit_type_display`.
- **The three exclusions in Decision 8** — correctness conditions, not thresholds. A flag to disable
  the merge-echo exclusion would be a flag to make the count wrong.

### Risks & Unknowns

1. **A quiet fix that is also a blind fix.** The failure mode is not noise, it is an hour that holds
   vehicles and says nothing — most plausibly via Decision 10's skip-not-consume interacting with
   `CALLOUT_MAX_AGE_S`: a member's event retires at 10 s while the set is held by the min-gap or the
   delta gate, and the contact then has no channel at all. Stage 3's acceptance bound (b) exists for
   this and must be checked by hour, not in aggregate.
2. **Decision 8(c) is O(n²) and unmeasured.** 2,652 `contacts_plausibly_same` evaluations per tick at
   n=52. If Stage 4 finds it material, the fallback is to run the exclusion only over contacts in the
   *triggering* hour rather than the whole store — strictly cheaper and strictly less correct
   (it misses an echo whose ancestor drifted to an adjacent hour). Do not pre-emptively weaken it;
   measure first. The project's own rule applies: a *reasoned* count is the figure most likely to be
   wrong by 2×.
3. **Hour-boundary oscillation from ownship yaw.** A contact at 44° moves between 1 and 2 o'clock on
   small heading changes, re-keying the set and its signature. Decision 11's gap bounds the audible
   effect; Stage 5 fixes the cause if Stage 3 shows it. The reason this is a risk and not a
   certainty: the signature excludes clock and range, so most drift produces no change at all.
4. **Where the 160 lines actually went.** Stage 3 may find the detection lines were not the bulk of

**A. Articles: *"Couple contacts"* or *"A couple of contacts"*?**

asked for — yields:

> *"Couple contacts, trucks, 2 o'clock, 6 kilometres."*

The 10-16 mock shows *"A couple of contacts, trucks, 2 o'clock, 6 kilometres."* That wording comes

(`speech.py:2642`), not from the shared register — so the project currently speaks this same hedge
two different ways, and the mock happened to be built from the inconsistent one.

**Recommendation: the brevity register, *"Couple contacts"***, since the 09-23 direction is explicit

**B. Does an escalating hedge count as a delta?**

You said *"delta"*, and the clear cases are a class appearing or disappearing. Decision 9 adds a
third trigger: the hour's hedge word crossing couple → handful → several → many.

- **With it:** sixteen vehicles filling 1 o'clock produce at most four lines, each one telling you

**Recommendation: include it.** It is the only thing that makes *"how much is out there"* — the
