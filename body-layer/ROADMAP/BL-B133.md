# BL-B133 — Petrovich does not start talking while the player keys ICS or RADIO

- [ ] **Petrovich does not start talking while the player holds the ICS or RADIO trigger.** #status/open Filed 2026-11-20 by user direction, to do after the 2026-11-20 BL-16 flight-mode fixes: *"when player presses ICS / RADIO trigger, while either is pressed, Petrovich does not start talking. This prevents him speaking while I'm speaking."* The trigger state already exists on the wire: `aircraft-layer`'s `GET /ptt/latest` (`schema/ptt.py`) carries both seats' triggers (args 738 and 856) as an OR, `intercom`/`radio`; its one consumer today is `audio-adapter`'s `ptt_source.py`, and body-layer does not read it. Shape to decide at build time: hold the start of a new utterance (the `SpeechWorker` queue or `CrewConsole._print`'s gate, beside the existing SPU-8 intercom hold) while either trigger is down; the two-stage trigger's 19-32 ms intercom transit on a full pull needs the same debounce `ptt_source.py` already applies. **Decided 2026-11-20** (user, verbatim): *"1 - say urgent ones even when I hold trigger 2 - let it play"*. So urgent lines (`urgent=True`, e.g. a forced "You have controls!") are never held; a line already playing when the trigger goes down plays to the end. Only the *start* of a routine line waits.
