# BL-B126 — `PUT /rules`/`/transcribe` have no cap on body size or list length

- [ ] **BL-B126 — `audio-adapter`'s `_read_body` reads `Content-Length` bytes with no upper
  bound, and `_handle_put_rules` parses an arbitrarily long `"rules"` list with no cap on list
  length or per-pattern string length — `compile_rules`'s own collision check (`rule_patterns.
  compile_rules`) is O(n²) over the accepted rule count. Both are pre-existing posture (`/speak`/
  `/transcribe` had no body cap before `[[BL-17]]` either) rather than something this feature
  introduced, but `PUT /rules` is new and inherits it.** Filed 2026-11-17 by the Security agent's
  Mode 2 deep analysis of `[[BL-17]]` Stages 0/1b/2 (`feature/speech-rules`, `plans/speech-rules/
  security-stage0-2.md`), as a non-blocking suggestion.

  **Why not blocking.** `server.py`'s `DEFAULT_HOST = "127.0.0.1"` — loopback only — and the
  module docstring states body-layer's `AudioAdapterClient` is expected to run on the same box as
  this server; the only real-world caller of `PUT /rules` is body-layer itself, re-pushing the
  rule set it just loaded from local `*.lua` files it controls. Reaching this endpoint from the
  LAN requires the operator to have started `audio-adapter` with `--host 0.0.0.0` (or another
  non-loopback address) themselves — a configuration choice this feature neither makes nor
  defaults to. This project's own threat model (root `CLAUDE.md`'s "Agents" section, Security
  scope) names "infected computer in LAN scanning ports" as the realistic attacker, which this
  would matter to only if that `--host` override is ever used.

  **Recommended fix, if/when `--host` is ever widened past loopback for this server (or any sibling
  one) as a matter of course:** cap `Content-Length` the same way `_MAX_CORRELATION_ID_LEN` already
  caps that one field (same file, same justification: "a generous cap costs nothing and forecloses
  an attacker-controlled LAN peer growing [a resource] without bound"), and cap the `rules` list
  length/pattern length before `compile_rules` runs its O(n²) pass over it.
