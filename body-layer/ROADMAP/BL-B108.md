# BL-B108 — Relative-distance grouping: one group is one contact, two groups on one bearing are two

- [x] **BL-B108 — Group decisions use Petrovich's relative judgement of distance, not his absolute
  range. The range error becomes stable per view (same place, same answer) and shared by nearby
  things, and decorrelates only with closing, line-of-sight rotation or a better optic. The
  merge zone becomes near-circular. Absolute spoken range keeps today's error.** #status/done

  **Review follow-up, 2026-10-31**: the first review found E1 (two groups on one bearing stay two
  contacts) reopened by an ordinary optic switch alone (Petrovich's own autonomous
  binoculars-raise mid-scan), since the shipped model zeroed the cross-optic correlation
  outright and the gate fell back to the pre-fix independent-sum width. First fix,
  `CROSS_OPTIC_RANGE_SHARE` (a flat shared fraction of the same-optic `Z_view` kernel), closed the
  one scenario it was built against but **did not generalise**: round 2 found no value within the
  tunable's own declared range preserved the plan's own same-optic "clear case" guarantee
  (1.5 km apart at ~3 km) once a look was cross-optic, at a separation more representative of
  ordinary tactical spacing than the one shipped scenario.

  **Amendment, 2026-11-01 ("cross-optic error model")**: retired `CROSS_OPTIC_RANGE_SHARE` and
  replaced the flat share with a tiered (nested) field — each optic's field is built on the
  shared core of every tighter optic's own realisation, so two ladder optics correlate at exactly
  `min(k)/max(k)` of their own range-scale ratio, the honest boundary where fusing them never
  extrapolates past either input. Running the real code against an ensemble of field
  realisations (not one draw) found the honest model meets the clear-case guarantee **same-optic
  (≤1% fold) and whenever both groups are in the same look (0% fold)**. It does **not** meet it
  cross-optic when the far group is held only in memory (an unaided estimate carries blur a
  binocular look does not share) — measured 0-86% on the shipped code across the clear-case grid
  (worst: far group glassed at 4.5-5 km, near group then seen unaided, far first; the architect's
  prototype said 5-67% because it lacked the gate's hypothesis-range rescale). **User decision
  (2026-11-01): accept this for now; closing it is the follow-on "check the expected area"
  feature (`plans/relative-distance-grouping/explore-notes.md`, last two sections).**
  E1 is delivered same-optic and whenever both groups are in view; the memory-only cross-optic
  rate is documented and fenced by `tests/test_relative_distance_sweep.py`
  (`test_e1_cross_optic_memory_only_fold_rate_is_fenced`), not asserted as solved. A second
  calibration change, `RANGE_DECORRELATION_RANGE_RATIO` 1.5 → 4.0, makes the same-optic clear case
  (2 km vs 2.5 km vs 5 km, the user's own words) actually hold at the stated range ratio — at 1.5
  the pair was only 8% correlated, which contradicted both the user and the plan's own table.
