  **What was built (D1, D3-D6; D2 measured and explicitly not shipped):** D1 drops "alt" from the
  `set_altitude`/`hold_altitude` patterns' whisper-prompt bias — "altitude" is the only word now.
  D2 (a prompt experiment to make whisper write numeral digits for composed number words) was
  tried, benched worse on every count, and not shipped — the spoken form for numbers stays
  individual digits ("three zero" for 30). D3 adds a deterministic digit-word homophone table
  (to/too→two, for/fore→four, free/tree→three, won→one, ate→eight, niner→nine, oh→zero),
  deliberately scoped to fire only inside an already-anchored numeric slot — a general char-ratio
  fuzzy fallback was measured and rejected as unsafe (ordinary words like "degrees"/"right" clear
  the same floor against a digit word). D4 maps "alright"/"all right" to "right" for the HVRT
  bare-word shortcut only, not a global normalization fold (the global version was tried and
  reverted after it widened an existing "right"~"sight" fuzzy collision to ordinary free speech).
  D5 (added mid-implementation, user-approved) blocks a bare direction word + unaccounted number
  from ever resolving to the legacy `point` command — fixes "right 45"/"left 30" (a dropped "turn")
  silently firing `point`. D6 (added mid-implementation, main-loop decision) fixes a genuine
  pre-existing defect found while implementing D3: `flight.lua`'s real `turn_heading` pattern
  required the literal word "heading" twice to match at all; "turn heading three one five" (what a
  pilot actually says) never matched before this fix.

  **Bench result, a deviation from the plan's own acceptance wording:** `phrase_bench.py`'s A_full
  row went 141→139 `ok`, WRONG 1→0 (the one targeted defect, "alright"→`point`, is gone). The
  plan's acceptance said "correct count up"; the actual count is down by 2, fully traced (3 clips
  are the now-retired "alt" phrasing, D1's own intended cost; 2 are an unrelated prompt-length
  wash) and accepted by the Reviewer as a reasonable, evidenced judgment call rather than a
  required fix — but it is a literal miss against the written acceptance line, recorded here
  plainly rather than glossed over.

  **Second-order effect on `[[BL-17]]`'s remaining stages:** the D6 defect (a slot type's own
  `sample()` baking in the same wrong assumption its `consume` required, so `check_rules.py`'s
  self-match step could not catch it) is a blind spot in the self-match checker itself, not just
  this one rule — any future rule-authoring stage that reuses a slot type this way inherits the
  same risk until the checker gains an independent oracle (a real bench corpus run through it).
  Noted as a follow-up, not built here (see `implementation.md`'s Notable Discoveries).
