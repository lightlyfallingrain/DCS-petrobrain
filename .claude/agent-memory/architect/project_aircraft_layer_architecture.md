Aircraft layer is a new sibling subproject `aircraft-layer/` (parallel to `world-model/`), not nested inside it. First plan: `plans/aircraft-layer/plan.md`, scoped to read-only kinematic telemetry only (position/attitude/heading/speed/alt) — switches, commands, contacts, weapons all explicitly deferred to follow-on milestones, mirroring how `world-model/ROADMAP.md` sequenced M0→M9 rather than planning the whole pipeline at once.

**Why:** This is the first component that does live-runtime DCS I/O (as opposed to World Model Builder's offline file/Lua-source parsing), and it's the first place a bidirectional LAN command surface will eventually exist. Investigator findings (`world-model/research/2026-09-06-aircraft-layer-live-runtime-io.md`) established: `Saved Games\DCS\Scripts\Export.lua` is a separate, unsanitized-by-default Lua environment (ships with LuaSocket, unlike Mission Scripting which needed the M4 `MissionScripting.lua` edit) that can push ownship kinematic state (`LoGetSelfData` family, not anti-cheat-gated) over a LAN socket with no new install-tree edit. Switch state needs DCS-BIOS (separate mechanism, Mi-24P coverage unverified) and sensor contacts have no real API — DCS-BIOS maintainers explicitly said "we don't normally export these sorts of things"; the only realistic path is `LoGetWorldObjects` ground truth + an external LOS/range filter, which is body-layer work.

**How to apply:** Three-hop pipeline locked in — DCS → Export.lua (push-only, dumb, in-process) → local collector process (same Windows box, Python, holds most-recent-state cache) → LAN JSON API (Windows→Mac). Export.lua never listens for/answers Mac requests directly, to keep DCS's sim-thread code minimal and keep the LAN-facing surface as an independently testable Python service. World Model query interface was explicitly assigned to the **body layer, not aircraft layer** (division-or-responsibility.md left this open) — aircraft layer's contract stays "DCS I/O only," World Model queries are static reference data fused by the body layer. The existing `world-model/WORKFLOW.md` Dropbox-symlink manual-copy workflow is confirmed **unsuitable** for this — it's async offline file transfer only; aircraft layer needs a genuinely new live LAN socket channel, documented separately in `aircraft-layer/WORKFLOW.md`. Command channel (switch actuation, Stage "Follow-on Milestones") is flagged as needing an explicit Security plan-review pass — it's a bigger untrusted-input-adjacent surface than World Model Builder ever had, so the project's blanket "skip security this phase" exemption should not apply to it specifically.
