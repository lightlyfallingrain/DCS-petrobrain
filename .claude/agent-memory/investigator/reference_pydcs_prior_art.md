github.com/pydcs/dcs (LGPL-3.0) ships per-theatre Transverse Mercator projection params under
`dcs/terrain/<theatre>/projection.py` (generated by `tools/export_map_projection.py`) and per-airbase DCS-native
x/y (=DCS x/z) positions under `dcs/terrain/<theatre>/airports.py`. Its projection fitting method
(`tools/coord_export.lua` + `tools/export_map_projection.py`) is itself a good template for our own
mission-scripting probe: dumps `coord.LOtoLL` for theatre origin + every `world.getAirbases()` entry via a
`DO SCRIPT FILE` trigger in a live mission, then curve-fits tmerc params.

Caution: pydcs's airbase "ground truth" lat/lon values are themselves derived from `coord.LOtoLL`, not an
independent real-world database — do not treat pydcs internal self-consistency as external validation. Always
pair with an independently-published real-world coordinate (e.g. an airport's published ARP) for genuine
control-point validation. See [[project_syria_projection]].

GitHub raw file fetches worked fine via WebFetch (raw.githubusercontent.com); GitHub repo root page and
directory listings needed api.github.com/repos/.../contents/<path> instead of the human-facing github.com page
for reliable content extraction. `gh` CLI is not available in this environment; `git clone` to /tmp is blocked
by the Bash sandbox permission system — use WebFetch against api.github.com/raw.githubusercontent.com instead.
