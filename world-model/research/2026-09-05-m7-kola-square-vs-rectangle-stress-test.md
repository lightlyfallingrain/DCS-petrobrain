# M7 — Kola as a stress test for the square-region-model assumption

**Date:** 2026-09-05
**DCS version:** not verified locally — no live DCS access to Kola from this session (this
Mac cannot reach the Windows DCS install this session; see `world-model/WORKFLOW.md`)
**Theatre:** Kola (DCS: Kola by Orbx), used only as a comparison stress case against Syria —
no Kola pipeline work is in scope

### Question

Architect was about to recommend keeping `RegionDefinition` (in `src/build/region.py`)
square-only (centre + single half-extent) for M7's full-Syria region, reasoning that
Syria's real-world bbox (~827x771 km, aspect ratio ~1.07) is close enough to square that
a square region only overshoots ~7-8% on the short axis. The user asked whether Kola — a
much higher-latitude theatre already installed, sharing the same `.routes`/`.rn4`/
RasterCharts asset pattern as Syria per `2026-09-03-m5-roadnet-file-recon.md` and
`2026-09-03-m2-rastercharts-recon.md` — falsifies this "square is good enough"
generalization, via two distinct possible mechanisms: (a) Kola's real-world footprint
being more elongated than Syria's, and (b) transverse Mercator distortion/grid convergence
growing at high latitude, degrading the "DCS x/z square == real-world square" assumption
that the square-only model quietly relies on.

### Findings

- **Kola has no `THEATRE_PROJECTIONS` entry — only Syria is implemented.** — **evidence:**
  reproduced-locally — **source:** `world-model/src/coordinates/projections.py` (read this
  session, single dict entry `"Syria"`). Kola coordinate transform is entirely
  unimplemented; nothing in this repo currently depends on getting it right, so this
  investigation carries no immediate correctness risk, only an architectural-generalization
  one.

- **Kola's tmerc parameters ARE derivable, from the same tool/source class that produced
  Syria's (later confirmed live).** — **evidence:** forum/community-tool-derived,
  unverified against live DCS — **source:** `pydcs`
  (github.com/pydcs/dcs, LGPL-3.0) `dcs/terrain/kola/projection.py`, fetched this session:
  ```
  PARAMETERS = TransverseMercator(
      central_meridian=21, false_easting=-62702.00000000087,
      false_northing=-7543624.999999979, scale_factor=0.9996,
  )
  ```
  This file is auto-generated by pydcs's `tools/export_map_projection.py` — the identical
  generation pipeline that produced Syria's params, which M1
  (`2026-09-03-m1-coordinate-transform-verification.md`) later confirmed against live
  `coord.LOtoLL` to 0.00-0.03 m residual. Same provenance class as Syria's *pre-M1* state:
  plausible and probably correct, but **not independently confirmed for Kola** — no live
  Kola DCS access was available this session. Treat as "provisional", not "confirmed", per
  `TmercParams.confidence`.

- **Kola's real-world footprint is genuinely, substantially more elongated than Syria's —
  this is a real, evidence-backed difference, not folklore.** — **evidence:** documented
  (ED/Orbx product marketing) + reproduced-locally (pydcs airport-position bbox) —
  **source:**
  1. ED/Orbx official product marketing (via web search this session, Stormbirds.blog +
     digitalcombatsimulator.com/Orbx FAQ coverage): Kola spans **~1,400 km east-west by
     ~1,000 km north-south** — aspect ratio **~1.4**. (Same caveat as Syria's marketing
     figures in `2026-09-05-m7-syria-theatre-extent.md`: a round marketing number, not
     exact corners.)
  2. Cross-check via `pydcs`'s own Kola airport position table (`dcs/terrain/kola/
     airports.py`, 9 airfields: Banak, Rovaniemi, Kemi Tornio, Vuojarvi, Kiruna,
     Severomorsk-1, Severomorsk-3, Bodo, Olenya) — DCS-grid (x, y) extremes:
     x range -243,396 to 234,846 m (**478 km**), y range -348,337 to 451,986 m
     (**800 km**), ratio **~1.67**. This is a point-cloud lower bound (same methodology
     class as the Syria airbase/beacon bbox in `2026-09-05-m7-syria-theatre-extent.md`),
     using only 9 of Kola's airfields (the local file listing shows ~29 `.rn4` taxiway
     files for Kola, i.e. more airfields exist than pydcs's table currently lists — see
     `world-model/data/raw/dcs/2026-09-02/DCS-files.txt`), so the true bbox is probably
     wider still.

     Both the marketing figure and the airport-position bbox agree Kola's long axis is
     ~1.4-1.7x its short axis — well outside Syria's ~1.07. **This is a real reason a
     square-only region model wastes significant area/compute on Kola-shaped theatres**:
     a square sized to cover the long axis (e.g. half-extent ~700 km to cover a ~1400 km
     span) would overshoot the short axis by 40-70%, not Syria's ~7-8%.

- **Transverse Mercator's local conformality means a DCS x/z square DOES still correspond
  closely to a real-world square at Kola's latitude — grid-convergence/scale-factor growth
  is NOT, on its own, a threat to the square-region assumption.** — **evidence:**
  reproduced-locally (pyproj probe, this session) — **source:**
  `world-model/tools/m7_kola_square_distortion_probe.py`. Method: construct a *true
  geodesic* square (fixed distance + bearing from a center point via `pyproj.Geod`, not a
  lat/lon-box approximation, which is itself non-square near high latitudes due to
  meridian convergence and would confound the measurement) and project its corners into
  each theatre's DCS x/z grid via the theatre's tmerc params, then measure edge-length
  ratios and corner angles.

  Results:
  | case | half-extent | N/S edge ratio | W/E edge ratio | corner angle deviation from 90 |
  |---|---|---|---|---|
  | Syria, theatre center (34.6N, 38E) | 250 km | 0.99999 | 1.00113 | -0.03 deg |
  | Kola, theatre center (67.5N, 27E) | 250 km | 0.99970 | 0.99689 | +0.09 deg |
  | Kola, theatre center (67.5N, 27E) | 500 km (stress) | 0.99939 | 0.99378 | +0.17 deg |
  | Kola, near theatre edge (69N, 33E, offset from lon_0=21 by 12 deg) | 250 km | 0.99886 | 0.99428 | +0.19 deg |

  Even at Kola's latitude, 500 km half-extent (a 1000x1000 km square, i.e. near the scale
  of the *entire* theatre), and offset toward the theatre's edge (12 degrees from the
  central meridian), edge-ratio deviation from 1.0 stays under 1% and corner angles stay
  within ~0.2 degrees of square. This is the expected behavior of a conformal projection
  (angles/local shape are preserved at a point; only overall scale factor `k` varies
  smoothly with distance from the central meridian) — it confirms the user's intuition
  that distortion *grows* with latitude/distance from center is directionally correct as a
  statement about scale factor, but that growth does **not** manifest as square-vs-
  non-square skew at region-sized scales. The mechanism the user hypothesized (tmerc
  distortion breaking square-ness) is not what actually threatens the square assumption —
  Kola's elongated *map footprint* (finding above) is a wholly separate and much larger
  effect than any latitude-driven projection anisotropy.

### Reproducible Test

`world-model/tools/m7_kola_square_distortion_probe.py` (this session) — run with
`world-model/.venv/bin/python3 tools/m7_kola_square_distortion_probe.py` from
`world-model/`. No live DCS access required; uses only `pyproj` (already a project
dependency) and the tmerc parameters quoted above.

### Possible Approaches

1. **Generalize `RegionDefinition` to rectangular half-extents (half_x, half_z) instead
   of a single square half-extent**, keeping square as the Syria-degenerate case
   (half_x == half_z). This is a small, low-risk change (adds one field, all existing
   Syria call sites keep working with half_x=half_z) and removes the latent assumption
   that would silently waste 40-70% area if this pipeline is ever pointed at Kola or a
   similarly elongated theatre (Kola is not the only such case — theatre shape is an ED
   art-team choice per map, not something this pipeline controls).
2. **Defer the generalization and keep square-only for now, but record the Kola finding
   as a known limitation** to revisit explicitly if/when a non-Syria theatre is scheduled.
   Valid if Architect judges M7 should stay minimal-scope (Syria-only, per
   `CLAUDE.md`'s "World Model Builder... Syria" current-priority framing) and the
   rectangular generalization is trivial enough to add later without rework of anything
   built against the square-only interface now.
3. Either way, **do not implement a Kola `THEATRE_PROJECTIONS` entry** from this
   investigation's pydcs-derived numbers without a live confirmation pass (an M1-style
   `coord.LOtoLL` probe at a handful of known Kola points, e.g. the airfields listed
   above) — this note establishes plausibility and aspect ratio only, not confirmed
   coordinate-transform correctness.

### Unresolved

- Kola's tmerc parameters are unverified against live DCS (no local Kola install /
  Mission Scripting access from this session). Evidence that would resolve it: a live
  `coord.LOtoLL` probe against a handful of Kola airfields (e.g. Banak, Kirkenes,
  Severomorsk-1), the same method M1 used for Syria.
- The true Kola theatre bbox (vs. the 9-airfield pydcs lower bound and the round ED/Orbx
  marketing figure) is not established to the same rigor as Syria's
  airbase+beacon-derived bbox in `2026-09-05-m7-syria-theatre-extent.md` — Kola has ~29
  `.rn4` airfield files locally listed but only 9 are in pydcs's current airport table;
  a full extraction (analogous to Syria's `beacons.lua`/`world.getAirbases()` cross-check)
  was out of scope here and would need either a live probe or parsing all Kola `.rn4`
  files directly.
- Whether any *other* installed/future theatre has an even more extreme aspect ratio than
  Kola's ~1.4-1.7 (e.g. very long, narrow maps) was not surveyed — Kola was checked only
  because the user named it as the specific stress case.

### Bottom line for Architect

Kola **does** provide real, evidence-backed grounds to make the region model support
rectangular half-extents — but for a different reason than the one hypothesized (theatre
map-footprint elongation, an ED art-team artifact, not tmerc projection distortion, which
this session's probe shows stays a non-issue for square-ness even at Kola's latitude and
near its edge). Confidence: **high** on "Kola is meaningfully non-square" (two independent
sources agree it's ~1.4-1.7x elongated vs Syria's ~1.07x) and **high** on "tmerc distortion
alone would not have broken the square assumption" (direct reproducible computation, not
inference). Confidence is **lower** (provisional) on Kola's exact numbers pending live
confirmation, but the square-vs-rectangle *architectural* conclusion does not depend on
those exact numbers — even the conservative 9-airfield lower bound (ratio 1.67) is decisive
against "square is close enough," so this conclusion is robust to Kola's precise bbox being
refined later.
