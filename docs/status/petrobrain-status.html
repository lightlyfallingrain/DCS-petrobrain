What the drawing shows that the lists do not. Every red node from the last drawing is gone. The five-fix sortie flew and passed; the voice-command sortie flew and passed, taking the joystick probe and the capture-clip blocker with it. What replaced them is one new red node, upstream of five branches instead of six — smaller, and for a different reason: three milestones merged unflown by deliberate user decision, not because a probe was still pending.

The fourth group is the real finding. Drawing the brain as one hold node at the right edge of three chains made it look like a single, ordinary dependency. It is not: four separate, already-built things — free-text commands arriving and being silently dropped by NullBrainClient, BL-7's mission-phase tie-break that no code path in a sortie ever calls, MI-5's question set that only ever asks about threats, and BL-8's kneeboard design that is waiting on judgement no fixture can supply — converge on a component with no plan file. The brain is not the next milestone; it is the one thing four milestones are already finished except for.

The reporting chain is otherwise unchanged: threat banding still needs believed coalition, which needs terrain control, which does not exist in world-model at all. threat-levels.md reads like one table; drawn out, it is still the longest unbuilt chain in the project that isn't waiting on the brain.

Open work

Milestone-level only. The reasoning behind each — why a constant moved, what an earlier pass got wrong — stays in the roadmap files, which remain the source of truth.

body-layer
Detection under real conditions

Every detection test so far was flown in near-perfect visibility, which makes the current calibration a ceiling rather than an average. Weather, light and vegetation multiply down from it. No longer blocked: ED's own detection model was read on the Windows box, and it decomposes the problem better than our sketch did — including sampling tree geometry for line of sight, which we do not.

Unblocked
body-layer
Attention capture — nothing outside the cone can interrupt him

The scan loop gave him a 30° focus cone, and Optic.peripheral is wired with no triggers behind it. So a muzzle flash at 3 o'clock while he looks at 10 produces nothing. This is a standing exposure created deliberately by 2C, not an oversight — and it is the most likely explanation for the pass where a unit flown past at close range was never identified.

Next
audio-adapter
Cockpit state drives the audio

The SRS dependency is dropped — it was never wired, and Windows audio through the collector already did the job. What replaces it is better: the intercom switch gates the crew channel in both directions, and the SPU-8 volume knob sets how loud he is. One physical control turns Petrovich on and off, exactly as the real one does. Deferred at your direction — and its one prerequisite is already gone: the device argument numbers were read off the install.

Deferred
body-layer
Repetition is better but not gone

Aggregation works on same-type, same-range, adjacent-clock contacts, and the five-fix sortie's transcript shows it firing — but five presence-level calls in one sector, differing only in range, are not aggregated, because range is exactly the part that carries no information at presence level. Two candidate rules, neither chosen yet.

Reopened
audio-adapter
Press-to-readback is ~3s

Measured on the voice-command sortie. A crew member answers in well under a second, so this is what will keep Petrovich feeling like a machine no matter how good recognition gets. One component is certain rather than estimated: the logger polls transcripts once a second, so half a second is spent purely being noticed.
