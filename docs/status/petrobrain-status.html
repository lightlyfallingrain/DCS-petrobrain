Petrobrain Milestones

Six subsystems now, one hundred and fifty-six tracked items — because the brain layer exists. It was the only component with no plan file and four finished milestones queued behind it; a day later it is a running process with a plan, a chosen model, and a first slice merged: free text that used to be silently dropped now comes back as speech. Three sorties flew and closed — eyes-and-voice, position belief, and the damage/firing probes — and eyes-and-voice is the one worth reading about, because it came back with eight defects rather than a pass. The probes settled how damage will be seen: a hit shows as fire, not smoke, and fire is terminal — damaged, then burning, then gone — so "it’s burning" is a report about something already dead, not something to re-attack.

What the drawing shows that the lists do not. The fourth group changed meaning, not membership. Last time it was “waiting on the brain”: four already-finished things — free-text commands arriving and being dropped, BL-7's mission-phase tie-break that no sortie code path calls, MI-5's question set, BL-8's kneeboard — converging on a component that did not exist. The brain now exists, and drawn forward the group is a chain rather than a funnel: Stage 2 wires the real model, structured candidates make follow that tank resolvable, Stage 3 adds the A/B answer leg, and only then do the idle four have something to attach to. The funnel was never four dependencies; it was one, four times over.

One flight still sits upstream of nearly everything. Same shape as last cycle, different flight: the crew-behaviour sortie gates recalibration, attention capture, conditions, the behaviour channel, stage 6 and latency — and now also feeds back into the brain's own prompt tuning. It is worth noticing that this is the second consecutive cycle where a single unflown sortie is the widest gate on the board, and that the previous one paid for itself: it returned eight defects, which is eight things that no fixture found.

What the probes bought. Damage and fire reporting moved from unknown to merely unbuilt, and it lands in the reporting group rather than perception — fire is not something to detect and classify but something to say, and it says something specific: fire is terminal, so a burning vehicle is a report about something already dead. That is a callout-wording problem, which is why it feeds the behaviour channel.

The reporting chain is otherwise unchanged: threat banding still needs believed coalition, which needs terrain control, which does not exist in world-model at all. threat-levels.md reads like one table; drawn out, it is still the longest unbuilt chain in the project.

Waiting on you, not on code

Two, same count as last cycle — but the first one is now carrying a whole day of fixes rather than a whole day of features, and the difference matters to how you fly it. Last time you were checking whether things worked; this time you are checking whether the fixes to what did not work are right.

Stage 1 proved the whole asynchronous round trip with a stub. The validator requires the model's evidence to appear verbatim in the candidate it picked — which is the right rule, and currently unsatisfiable: the candidate summaries carry no place names and no class/type structure, so nothing the pilot says can be a literal substring of them. Detection under real conditions

Every detection test so far was flown in near-perfect visibility, which makes the current calibration a ceiling rather than an average. Weather, light and vegetation multiply down from it. No longer blocked: ED's own detection model was read on the Windows box, and it decomposes the problem better than our sketch did — including sampling tree geometry for line of sight, which we do not. Unblocked
body-layer
Attention capture — nothing outside the cone can interrupt him

The scan loop gave him a 30° focus cone, and Optic.peripheral is wired with no triggers behind it. So a muzzle flash at 3 o'clock while he looks at 10 produces nothing. This is a standing exposure created deliberately by 2C, not an oversight — and it is the most likely explanation for the pass where a unit flown past at close range was never identified.

The double-line edges are DCS itself — read and written, never a one-way feed. The single plain edge between Body Layer and World Model is the one in-process import this project allows anywhere; every other subproject boundary, including the two crossing back to Windows, is HTTP. Mission Interpreter runs offline and hands off one artifact before a sortie starts — it has no seat in the runtime loop. The brain is no longer drawn as absent. Note which way its two edges point: body-layer hands an escalation over and does not wait, and the reply is drained in the ordinary poll loop. That is not an implementation detail — it is the constraint the whole layer was designed around, because the game world keeps moving whether or not Petrovich has finished thinking.
