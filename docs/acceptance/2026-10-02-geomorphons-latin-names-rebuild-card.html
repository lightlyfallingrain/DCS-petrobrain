Geomorphons Rebuild

One full-theatre build verifies two features at once: the geomorphons ridge/valley detector (WM-B6) and the Latin-script place-name preference (WM-B1). Neither takes effect until this runs.

Checkout

git checkout main && git pull, then confirm with git log --oneline -5 that you see both Merge feature/landform-geomorphons and Merge fix/latin-place-names. If only the latter shows, the geomorphons branch hasn't merged yet — wait for it.

Only you can run this

Real SRTM tiles, Syria.routes, towns.lua/beacons.lua, and the merged syria-theatre.osm.pbf are all gitignored — no agent has built or can build syria-full.sqlite. Per project rule, the real full-theatre build is yours alone to run.

What changed, in one line

WM-B6: the parked watershed detector is replaced by geomorphons classification at native ~90 m SRTM resolution, traced through junctions and smoothed, cached per tile. WM-B1: OSM place names now prefer a Latin-script name:en/int_name over raw (often Arabic) name. Nothing in the cockpit changes — the landform callout (Stages 3-5) isn't built yet.

Setup

From world-model/, venv active. Read straight from tools/build_world_model.py as it stands on the merged branch — no new flag for either feature:

cd world-model
.venv/bin/python tools/build_world_model.py syria-full \
    --towns data/raw/dcs/syria/map/towns.lua \
    --beacons data/raw/dcs/syria/map/beacons.lua \
    --routes data/raw/dcs/syria/roads/Syria.routes \
    --srtm-dir data/raw/dem/syria-full/ \
    --osm-pbf data/raw/osm/syria-theatre.osm.pbf

Overwrites data/world-model/syria-full.sqlite. --srtm-dir drives the terrain stage (cache path auto-derived, no flag); --osm-pbf drives OSM ingest, where the name preference applies.

Terrain-stage timing is extrapolated from 27 real tiles, not a measured 131-tile run — no agent can run the real build

Terrain stage: roughly 14 minutes of CPU time (down from an early ~25 min estimate after a memory/smoothing fix), one progress line per tile across all 131. Peak RSS for that stage: under ~1.8 GB, measured directly (not extrapolated) and confirmed flat across tiles rather than growing with theatre size.

Resumability: if you interrupt the build, re-running the same command skips SRTM tiles already processed — the terrain cache is a separate file that survives the base store's delete-and-rebuild. Verified by a direct unit test and a cold/warm timing measurement (16.65s → 0.75s on one tile), not by an actual kill of a live run.

Blocks

Block A

Ridge/valley counts — a different kind of number now

.venv/bin/python -c "
import sqlite3
conn = sqlite3.connect('data/world-model/syria-full.sqlite')
for row in conn.execute(\"select kind, count(*) from feature where kind in ('ridge','valley') group by kind\"):
    print(row)
"
Expect

The old watershed detector's theatre-wide counts were 8,189 ridges / 2,314 valleys — one feature per basin boundary. Geomorphons counts individual traced lines instead, so a much bigger number is the intended result, not a regression: a 27-tile sample during performance testing extrapolates to roughly 1.3 million combined features theatre-wide. Near-zero, or wildly off that extrapolation, is the actual red flag.

Block B

WM-B1 — did the Latin-name preference take effect?

.venv/bin/python -c "
import sqlite3
conn = sqlite3.connect('data/world-model/syria-full.sqlite')
row = conn.execute('''
  select
    sum(case when json_extract(tags_json, '\$.name_source') = 'name:en' then 1 else 0 end) as via_name_en,
    sum(case when json_extract(tags_json, '\$.name_source') = 'int_name' then 1 else 0 end) as via_int_name,
    sum(case when json_extract(tags_json, '\$.name_source') is not null then 1 else 0 end) as any_name_source,
    count(*) as total
  from feature
  where kind in ('named_place', 'settlement')
''').fetchone()
print(row)
"
Expect

via_name_en near 12,926, via_int_name near 864 (13,073 total yield), out of 49,226 named/settlement rows — from WM-B1's own measurement against the real merged extract.

What is NOT fixed

Region-scoped builds (e.g. latakia-20km) don't clip terrain output to the region's bbox — a region rebuild stores every ridge/ valley line any covering SRTM tile produces, not just the region's own extent. Doesn't affect this full-theatre build. Nothing in the cockpit changes — Stages 3-5 (adjacency, bearing, the callout) aren't built. A tile-seam case and a literal kill-mid-build resume were never exercised against real data, only unit-tested.
