SPU-8 Intercom Sortie

Acceptance flight — does the cockpit intercom panel actually gate Petrovich?

DoD · 2026-10-05
Check out this branch first
git checkout feature/spu8-intercom && git pull

DoD mechanical checks PASSED, Reviewer / Security / Performance all APPROVED. Not merged yet. If you're flying after it has merged, check out main instead — same setup and test items apply.

Fly this one alone

This changes whether Petrovich can be heard at all. Don't combine it with the contact-report sortie — if gating or volume is wrong here, you won't be able to tell "he didn't say it because the fix suppressed it" from "he didn't say it because the intercom was closed." Settle this flight first.

Right now Petrovich's audio has no real gate — he can always be heard and you can always be captured, disconnected from the cockpit's own intercom panel. This slice wires it up: pilot NET-1 (arg 377) AND co-pilot ICS power (arg 664) gate capture and playback both ways, and the SPU-8 volume knob (arg 457) scales his loudness. Two automatic defaults ride along: co-pilot ICS switches on by itself 5 seconds after spawn, and he starts silent on the ground.

Before you can fly at all

1Redeploy Export.lua

This branch bumps the export version to 2026-10-05 and adds the three new SPU-8 telemetry fields. A stale deployed copy gets refused (version-mismatch warning, not a crash) — the new fields just won't be there.

copy aircraft-layer\dcs-export\Export.lua "Saved Games\DCS\Scripts\Export.lua"

2Start the usual three processes

Mac side, from run-scripts/, Windows collector already running with the redeployed Export.lua.

cd run-scripts
./run-audio-adapter.sh
./run-brain.sh --decider ollama
./run-crew-text-debug-view.sh

3Confirm new telemetry is flowing

From the Mac, once the collector is up (swap in your own $DCS_COLLECTOR_IP from petrobrain.env):

curl http://$DCS_COLLECTOR_IP:7791/spu8/state

Expect null before you've touched the cockpit, then a JSON object with net1, ics_power, vol plus net1_on / ics_power_on / gate_open once DCS is exporting. This exact command was not run against a live DCS session from here — check it first, don't assume it.

Two numbers shipped as guesses, not measurements: ON_GROUND_AGL_THRESHOLD_M = 10.0 and MISSION_START_ICS_DELAY_S = 5.0. This flight is what calibrates them.
What to test
1

Gate — NET-1 off

DoOn the ground, turn the pilot's NET-1 switch OFF (arg 377). Key the ICS PTT and speak.
ExpectNo capture at all — collector/debug log shows no change. A queued line from Petrovich goes silent, not queued for later.
2

Gate — co-pilot ICS off

DoNET-1 back ON. Turn the co-pilot ICS power switch OFF (operator panel, or catch it after the mission-start auto-write and flip it off).
ExpectSame closed-both-ways result as test 1 — either switch alone closes the channel.
3

Gate — both on

DoTurn both NET-1 and co-pilot ICS ON.
ExpectCapture and playback both work normally.
4

Volume knob

DoGate open. Turn the SPU-8 volume knob between two of Petrovich's callouts.
ExpectAn audible loudness change. The new volume applies from the next line, not ramped into the current one — confirm that's not jarring in practice.
5

Mission-start auto co-pilot ICS

DoSpawn in, watch the co-pilot ICS switch (or poll GET /spu8/state) for the first 10 seconds. Don't touch it yourself.
ExpectIt moves to ON on its own, ~5 seconds after spawn.
6

On-ground silent start

DoStart on the ground, gate open. Give no command yet — just watch/listen if contacts are nearby. Then give any command (e.g. "report").
ExpectSilent before the command, even with contacts detected and the overlay/text still updating. Speech resumes after the command and stays resumed even after a later touch-down this sortie (one-shot, not re-armed by landing again).
7

Stutter check

DoJust fly normally for a few minutes with this branch's Export.lua running.
ExpectNo new stutter. Three extra unthrottled per-frame cockpit reads were added — reasoned as the same cost class as the existing PTT read, but there's no profiler for this. Only you can answer it.
8

Mission restart (optional, rides free)

DoIf convenient, restart the mission once this sortie.
ExpectThis branch also fixes a pre-existing bug where a restart silently stopped telemetry. Confirm /spu8/state (or any telemetry) still updates after a restart.
Pass criteria
Both gate directions work independently and together, the volume knob is audible with next-line timing that doesn't feel broken, the mission-start ICS write and on-ground silence each fire correctly and only once, and there's no noticeable stutter.

Bring back

  1. Did both switches independently close the channel, and did both-on restore it?
  2. Did the volume knob work, and did next-line-not-current feel right?
  3. Did the mission-start ICS write happen on its own around 5s?
  4. Was he silent on the ramp, and did the first command end it? Did takeoff alone leave him silent?
  5. Did the 10m ground threshold feel right, or should it be bigger/smaller?
  6. Any stutter, however slight?
  7. Did telemetry survive a mission restart, if you tried one?
Anything that surprises you is worth more than anything on this list.
