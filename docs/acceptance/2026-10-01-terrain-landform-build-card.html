Terrain Landform Build

A full-theatre rebuild, not a sortie. The ridge/valley detector was replaced end to end — this card checks the real output against what three small test regions already predicted, before Stage 3-5 ever reach the cockpit.

Checkout

git checkout feature/terrain-landform-features && git pull — this becomes main once merged; confirm with git log --oneline -3 that you're on the fix, not an older main.

Only you can run this

The real SRTM tiles, Syria.routes, towns.lua/beacons.lua are gitignored — no agent has built or can build syria-full.sqlite. Per project rule, the real full-theatre build is yours alone to run.

What changed, in one line

Old per-cell curvature noise — 11,749 ridges / 11,477 valleys on the 2026-09-30 build — is replaced by a marker-controlled watershed gated on relief and width. Nothing in the cockpit changes from this build: Stage 3 (adjacency), Stage 4 (bearing) and Stage 5 (the callout itself) aren't built. This only changes what lands in feature(kind='ridge'/'valley').

Block B

Fragmentation and sinuosity

.venv/bin/python -c "
import json, math, sqlite3, statistics
conn = sqlite3.connect('data/world-model/syria-full.sqlite')
for kind in ('ridge', 'valley'):
    rows = conn.execute('select geom_json, tags_json from feature where kind = ?', (kind,)).fetchall()
    n = len(rows)
    under_15 = 0
    sins = []
    for geom_json, tags_json in rows:
        coords = json.loads(geom_json)
        tags = json.loads(tags_json)
        if tags.get('cell_count', 999) < 15:
            under_15 += 1
        path = sum(math.hypot(coords[i+1][0]-coords[i][0], coords[i+1][1]-coords[i][1]) for i in range(len(coords)-1))
        end = math.hypot(coords[-1][0]-coords[0][0], coords[-1][1]-coords[0][1])
        if end > 0:
            sins.append(path / end)
    pct = 100.0 * under_15 / n if n else float('nan')
    med = statistics.median(sins) if sins else float('nan')
    print(f'{kind}: n={n}  pct_under_15_cells={pct:.1f}  median_sinuosity={med:.3f}')
"

Block C · the prize

Baalbek — the Bekaa must produce no valley

Unverified against real syria-full — names/coordinates confirmed from this session's research notes, the lookup itself not yet run on real data

.venv/bin/python tools/inspect_terrain.py data/world-model/syria-full.sqlite \
    --near Baalbek --radius-km 20 --out /tmp/baalbek.png
Why this is the one that matters

The Bekaa is a kilometres-wide flat basin — at Mi-24 flight profile, calling the whole floor "a valley" the way you'd call a narrow draw is meaningless (your own words from the Explore conversation that redesigned this detector). Three region-scoped rebuilds already confirmed the Baalbek-window dominant basin (1,020 cells, ~1,274 m relief, ~13.7 km core width against the 2,500 m ceiling) fails the width gate and produces zero valleys for the Bekaa body — this build is the first time that's checked against the real whole-theatre grid.

Expect

Zero valley components over the Bekaa floor itself. A small separate mountain-top basin near Baalbek is expected and fine.
