Check the residual

Run from world-model/, venv active. Verified this session against a synthetic file with the exact JSON shape the probe writes — only the real live numbers are unverified, since those need your flight.

cd world-model
.venv/bin/python -c "
import json, math, sys
sys.path.insert(0, 'src')
from coordinates import dcs_to_wgs84

def haversine_m(lat1, lon1, lat2, lon2):
    r = 6371000.0
    p1, p2 = math.radians(lat1), math.radians(lat2)
    dphi = math.radians(lat2 - lat1)
    dlmb = math.radians(lon2 - lon1)
    a = math.sin(dphi/2)**2 + math.cos(p1)*math.cos(p2)*math.sin(dlmb/2)**2
    return 2 * r * math.asin(math.sqrt(a))

data = json.load(open('data/raw/dcs/<today>/coord_probe_output.json'))
points = [{'name': 'origin', **data['origin']}, *data['airbases']]
worst = 0.0
for p in points:
    pred_lat, pred_lon = dcs_to_wgs84('Afghanistan', p['x'], p['z'])
    residual = haversine_m(p['lat'], p['lon'], pred_lat, pred_lon)
    worst = max(worst, residual)
    print(f"{p['name']:30s} residual_m={residual:.3f}")
print(f'worst residual across {len(points)} points: {worst:.3f} m')
"
Pass criterion

Worst residual ≤ ~0.1 m (Syria's M1 floor was 0.00–0.03 m). If every point clears it, flip confidence to "confirmed" in world-model/src/coordinates/projections.py and cite the new research note.

A residual in the metres, not sub-metre, at any point means the fit is wrong — don't flip confidence; write up the real numbers instead.

Don't discard

coord_probe_output.json's airbases array comes from world.getAirbases() — DCS's real registry, independent of beacons.lua. Right now this project only knows 7 of Afghanistan's ~26 airfields (the navaid-equipped ones). This file is the seed for the rest. Keep it.
