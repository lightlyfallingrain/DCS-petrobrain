PTT Speech Hold

BL-B133 — does Petrovich stay quiet while you're keying ICS or RADIO, 2026-11-24

Branch main once this DoD pass's auto-merge lands — git checkout main && git pull
No special setup — this is the production crew pipeline, not a probe. Fly normally, let Petrovich accumulate a few routine callouts before testing, so there's something queued to hold against. Two things this card does not settle: the exact debounce window and the 2-minute telemetry-staleness bound were chosen as agreed guesses (belief/ptt_hold.py), not measured — this flight is the first real data on whether they feel right.

1 Hold ICS through a routine line, then release

Do
Press and hold the intercom trigger while you expect a routine line (a contact callout, a status update) is about to come. Hold a few seconds, then release.
Expect
No new line starts while ICS is held. Shortly after release — a fraction of a second, not a noticeable delay — the line starts.
Record
Did anything start while held? How long from release to the line actually starting?

2 Same with RADIO

Do
Repeat block 1, holding the radio trigger instead of intercom.
Expect
Identical behaviour — either trigger holds routine speech, not just one of them.
Record
Any difference from how ICS behaved in block 1.

3 An urgent line speaks through a held trigger The prize

Do
While holding ICS or RADIO, trigger something that should produce an urgent line — a forced handback (“you have controls!”) is the clearest if one is available; any line you know is marked urgent works.
Expect
The urgent line speaks immediately, even though the trigger is still held down. It does not wait for release — this is the one behaviour the whole feature exists to not break.
Record
Did the urgent line speak while you were still holding the trigger, or did it wait?

4 Holding the trigger mid-line doesn't cut it off

Do
Let Petrovich start speaking a line, then press and hold ICS or RADIO partway through it.
Expect
The line already playing finishes normally — it is not cut off. Only the next line (if routine) waits for release.
Record
Did the in-progress line finish cleanly, or did it get cut off the moment you pressed the trigger?

5 A long held trigger optional

Do
If the flight runs long and you end up holding RADIO for an extended stretch (a couple of minutes or more) during a real exchange, just notice what happens.
Expect
By design, a held trigger is only trusted for as long as the telemetry feed itself keeps refreshing — this is the one open question in the implementation (see belief/ptt_hold.py's module docstring). A genuinely long hold under normal conditions should still hold; this block is the only way to probe it for real.
Record
Did Petrovich ever start talking over a long held trigger? Roughly how long had you been holding it?

Bring back

  • Blocks 1–2: did either trigger correctly stop a routine line, and how quick was release-to-speech.
  • Block 3: did the urgent line really speak through a held trigger.
  • Block 4: did an in-progress line ever get cut off.
  • Block 5, if you hit it: any talking-over on a long hold.
Anything that surprises you is worth more than anything on this list.
