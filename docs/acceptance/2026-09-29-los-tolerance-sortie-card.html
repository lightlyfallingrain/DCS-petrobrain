Will become main once merged — after checkout, git log --oneline -3 should show this fix, not an older main.

Not a standalone sortie. Fly this inside your feature/group-reporting acceptance flight — no conflict, nothing here needs its own dedicated sortie. Group-reporting is a callout-scheduling change; this is a terrain-LOS constant. One flight covers both.

Why this card exists. 2026-09-28: you flew close past an insurgent AAA position, boresight, on an attack run, attacked it — Petrovich never called it out, not once. Diagnosed offline: the elevation grid (SRTM, 1000m spacing, measured 11.52m stddev against DCS truth) can place a real unit below the modelled terrain at its own position, permanently blocking line-of-sight to it from every angle. Fixed with a 12m tolerance on the terrain check. Every test is a monkeypatched grid — it proves the arithmetic, not that Petrovich now calls the real position, and not whether the accepted cost below is actually mild. Only this flight settles either.

Setup

Same collector/brain/crew-text stack as your other current-branch sorties. From run-scripts/ on the Mac:

cd run-scripts
./run-audio-adapter.sh
./run-brain.sh --decider ollama
./run-crew-text.sh --detection-trace ~/dcs-detection-trace.jsonl

Fly with --detection-trace enabled (shown above — additive, no other behaviour change). Without it, a miss on this flight is exactly as unevidenced as the one that started this fix: belief-truth logging structurally cannot record a rejected candidate, only an admitted one.
